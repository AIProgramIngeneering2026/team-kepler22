# ADR-0003. Доступ по одному ключу команды без владельцев Job

**Дата.** 2026-11-15
**Статус.** Принято

## Контекст

Сервис разворачивает одна команда для себя. Пользователи это разработчики команды и её скрипты в CI. Нужно не пустить посторонних, иначе любой в сети запустит проверки и потратит лимиты внешних API. Карта К8 спрашивает, что будет при запросе чужого Job. Хранить персональные данные пользователей по правилам курса нельзя.

## Решение

Каждый запрос, кроме `/health`, должен содержать заголовок `X-API-Key`. Ключ один на команду и задаётся переменной окружения `VULNTRIAGE_API_KEY`, в репозитории его нет. Без ключа или с неверным ключом сервис отвечает `401 unauthorized`.

Владельцев у Job нет, все Job общие для команды. Номер Job это случайный UUID v4, его нельзя угадать перебором. Запрос несуществующего Job даёт `404 job_not_found`.

## Рассмотренные альтернативы

* **Учётные записи и владелец у каждого Job.** Позволяет разделить доступ внутри команды, но требует хранить пользователей, вход и сброс пароля. Это персональные данные и много работы не по теме проекта.
* **Ключ на каждого пользователя.** Видно, кто что запускал, но ключи нужно где-то выдавать и хранить.
* **Без аутентификации.** Проще всего, но сервис открыт всем, кто знает адрес.

## Цена решения

* Внутри команды доступ не разделён, любой участник видит и отменяет любой Job.
* Утечка ключа даёт полный доступ. Менять ключ нужно вручную и всем сразу.
* По логам нельзя понять, кто из команды запустил проверку.

## Когда пересмотреть

* Сервисом начнут пользоваться несколько команд. Тогда ключ на команду и владелец у Job.
* Понадобится аудит, кто запускал проверки.
