# VulnTriage

Сервис, который подсказывает, какие уязвимости в зависимостях проекта чинить первыми.

## Какую проблему решаем

Сканеры зависимостей выдают десятки уязвимостей, и почти все помечены как важные. Времени закрыть их сразу у команды нет, поэтому список обычно сортируют по CVSS, то есть по теоретической тяжести. Это плохо работает. Многие «критические» уязвимости никто не атакует, а некоторые «средние» уже атакуют массово.

С 15 апреля 2026 года ситуация стала хуже. NIST перестал обогащать все CVE в NVD и подробно обрабатывает только небольшую часть, поэтому у большинства новых уязвимостей больше нет оценки CVSS от NIST. Сортировать по одному CVSS теперь просто не по чему.

Мы сортируем по реальной опасности. Смотрим, атакуют ли уязвимость прямо сейчас (каталог CISA KEV) и насколько вероятна атака в ближайшие 30 дней (EPSS). CVSS учитываем последним.

## Для кого

Для разработчиков и DevOps-инженеров небольших команд, которые отвечают за безопасность своего проекта, но не имеют отдельного специалиста и платных сканеров. Им нужно быстро понять, что брать в работу на этой неделе.

## Как это работает

1. Команда загружает SBOM своего проекта в формате CycloneDX. Его можно получить одной командой через `syft` или `trivy`.
2. Сервис создаёт задачу проверки (Job) и сразу возвращает её номер.
3. По базе OSV.dev находит уязвимости в компонентах SBOM.
4. Для каждой уязвимости проверяет каталог CISA KEV и запрашивает оценку EPSS.
5. Распределяет уязвимости по уровням и отдаёт отчёт, где у каждой есть причина её места в списке.

Уровни такие. Пороги можно менять в конфигурации, код при этом не трогаем.

| Уровень | Условие |
|---|---|
| Срочно | уязвимость есть в KEV или пакет помечен как вредоносный |
| Скоро | EPSS от 10% или CVSS от 9 при EPSS от 1% |
| Плановое | CVSS от 7 |
| Можно отложить | всё остальное |
| Нет данных | нет ни CVSS, ни EPSS, показываем отдельно |

## Что входит в систему

* REST API с контрактом в OpenAPI.
* Задачи проверки с жизненным циклом и историей.
* Источники данных OSV.dev, CISA KEV и EPSS, каждый за своим адаптером.
* Правила распределения по уровням.
* Хранилище на PostgreSQL (на прототипе SQLite). В нём живут Job и их состояния, отчёты и кэш KEV, поэтому после перезапуска ничего не теряется.

## Что точно не входит

* Пользовательский интерфейс, работаем через API и Swagger.
* Генерация SBOM, мы принимаем готовый файл от утилит по типу syft, trivy или cdxgen.
* Автоматическое исправление уязвимостей в коде проекта.
* Сборка и запуск проверяемого проекта, сервису нужен только список зависимостей из SBOM.
* Форматы кроме CycloneDX JSON, SPDX можно добавить позже.
* Мониторинг по расписанию и уведомления.
* LLM в первом семестре.

## Второй семестр

Цифры говорят, насколько уязвимость опасна вообще, но не говорят, затрагивает ли она конкретный проект. Во втором семестре модель будет читать описание уязвимости и профиль проекта (веб-сервис или CLI, принимает ли данные из сети, какие функции использует) и предлагать вердикт «затрагивает / не затрагивает / нужно разобраться» в формате VEX. Вердикт утверждает человек. Утверждённые вердикты учитываются при следующих проверках.
